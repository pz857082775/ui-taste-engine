> 一个"审美积累"技能：把每次生成、评审、返工，变成一条可复用的知识卡；
> 按证据数量自动晋升或衰减，防止知识库变成自我吹捧的垃圾场。
>
> **它不是生成器，是判断力的积累器。** 与 [website-ui-designer](https://github.com/pz857082775/website-ui-designer) 配套使用。

[三分钟上手](#三分钟上手) · [怎么攒知识](#怎么攒知识) · [评估标准](#评估标准) · [版本历史](#版本历史)

## 它解决什么

| 你会遇到的 | 它怎么处理 |
|---|---|
| 每次都生成一样的"AI 脸" | 反例库（A 卡）：生成前强制过一遍禁令，命中就改 |
| 只会说"高级点""干净点" | 意图翻译层：20+ 条「原话 → 参数」对照，最多问你 3 个问题 |
| 风格总是那一套 | 风格组合 + 每页强制一个"签名细节" |
| 不知道哪个版本更好 | 三轴评分卡 + 盲评三问 + 10 例固定回归集 |
| 经验记了但没人用 | `use` 计数 + 复用率指标；90 天不用自动降级 |

## 三分钟上手

### 第 1 步 · 放到技能目录

```bash
# 直接克隆
git clone https://github.com/pz857082775/ui-taste-engine.git ~/.workbuddy/skills/ui-taste-engine

# 或拷贝到你 Agent 的技能目录（Claude Code 用 ~/.claude/skills/）
```

无需安装依赖。Python 3.9+ 即可，只用标准库。

### 第 2 步 · 看一眼库里有什么（30 秒）

```bash
cd ~/.workbuddy/skills/ui-taste-engine
python scripts/kb.py list
```

你会看到 12 张卡：参数 3 / 手法 4 / 反例 2 / 判断 2，含 26 张真实截图的分析结论。

### 第 3 步 · 用起来（三种最常用）

```bash
# ① 生成页面前：先查这个场景有哪些已知规则
python scripts/kb.py list --type A          # 看反例，避开已知坑
python scripts/kb.py list --type P          # 看参数，直接用数值

# ② 生成页面后：把这次的经验记下来
python scripts/kb.py add my-card.md         # 会校验字段，不合格拒收

# ③ 每周体检：看库有没有腐烂
python scripts/kb.py check                  # 格式问题 / 重复 / 待衰减
python scripts/kb.py stats                  # 复用率 / 置信分布 / 衰减率
```

> **小白用法**：你甚至不用敲命令。直接对 Agent 说
> "把'移动端正文行高至少 1.7'记进知识库，来源是这次咖啡店页面"，
> 它会自己生成卡片、跑校验、入库。

## 怎么攒知识

### 四类卡（一卡只讲一件事）

| 类型 | 装什么 | 例子 |
|---|---|---|
| **P 参数** | 具体数值 | 强调色每屏 3-5 次 |
| **M 手法** | 可复现的结构 | KPI 卡四段：图标软底 → 标签 → 28px 数字 → 趋势 |
| **A 反例** | 错误 + 替代方案 | CSS 预隐藏致 CDN 失败整页空白 |
| **J 判断** | 什么时候用哪个 | 趋势色按领域定，全站只能一种 |

### 五个来源（都必须能追溯）

1. 生成任务的结果（这次用了什么参数、一次通过还是改了 3 轮）
2. 评审与修复的配对（诊断出什么 → 用什么处方）
3. 用户反馈（"不好看"要追问到具体维度：太挤？太土？没重点？）
4. 外部参考拆解（带 URL + 日期）
5. 失败案例（AI 味清单，越用越准）

### 晋升规则（防止自我吹捧）

```
候选(1) → 复现(2) → 稳定(3) → 默认(4) → 公理(5)
```

- 只有 1 次证据的卡，置信度最多 2，**不许进默认规则**
- 想升到 4：证据 ≥3（来自 ≥2 个任务）→ 过 10 例回归（均分不降 >2）→ 写回规范文件
- 90 天不用自动降 1 级，180 天转 stale，365 天归档
- 同一场景两条规则冲突：按证据强度 → 范围具体度 → 时间新近裁决，**必须留书面理由**

> **宪章条款**：评分权重、验收条、置信度定义、本协议本身，AI 不能自己改。
> 否则"自我进化"会变成"自我讨好"——分数越来越高，界面越来越差。

## 评估标准

| 指标 | 怎么算 | 及格 | 目标 |
|---|---|---|---|
| 盲评胜率 | 新旧两版并排，三人盲评"哪版更像人做的" | 60% | 85% |
| 一次通过率 | preflight 0 + 验收条全过 + 零返工 | 基线 30-40% | 70% |
| 平均返工轮次 | 用户提出修改的次数 | — | ≤1.5 |
| 知识复用率 | 被 `use` 引用过的卡 / 总卡 | ≥50% | ≥70% |
| 高置信占比 | 置信 ≥4 的卡 / 总卡 | 20-35% | 30% |
| 衰减率 | 近 90 天降级 / 总卡 | 5-15% | 10% |

**专业度阶梯**：L1 不难看 → L2 有风格 → L3 有判断（能解释并给替代）→ L4 能预判。
本技能承诺 L1→L2 稳定、L3 可复制；**L4 不承诺**（需要长期真实项目积累）。

## 命令速查

| 命令 | 作用 |
|---|---|
| `kb.py list [--type P\|M\|A\|J] [--status active]` | 列出卡片 |
| `kb.py show <ID>` | 看某张卡全文 |
| `kb.py add <卡片.md>` | 校验后入库（不合格拒收） |
| `kb.py use <ID>` | 记一次复用（提升复用率指标） |
| `kb.py promote <ID>` | 晋升一级（证据不足会被拒） |
| `kb.py decay` | 按 last_used 批量衰减 |
| `kb.py check` | 健康检查：格式 / 重复 / 待衰减 |
| `kb.py stats` | 输出指标表 |
| `kb.py index` | 重建 INDEX.md |

## 对外检索接口

本库的知识卡可直接被 `website-ui-designer` 的检索引擎读取（零依赖，无需额外服务）：

```bash
# 在 website-ui-designer 目录下
python scripts/rag.py index                                  # 会同时索引本库四类卡
python scripts/rag.py query "强调色用几次" --type P --format prompt
```

索引以 BM25 + 中文二元组 + 口语同义词实现，知识卡按置信度加权；无命中时输出"无依据"，
不编造条款。详细规则见 `website-ui-designer/references/rag-retrieval.md`。

## 常见问题

**我需要懂设计才能用吗？**
不需要。你只要描述"哪里不对"（太挤 / 太土 / 没重点 / 太像 AI），它会翻译成参数并记下来。

**它会自己乱改自己的规则吗？**
不会。晋升需要证据 + 回归验证，核心规则（评分权重、验收条、置信度定义）属于宪章，只能人工改。

**知识库会不会越记越乱？**
有三道闸：拒收规则（缺来源/太笼统/重复）、健康检查（重复/格式）、自动衰减（90/180/365 天）。

**和 website-ui-designer 是什么关系？**
前者负责"生成"，本技能负责"越生成越准"。单向流动：知识库 → 设计器。
